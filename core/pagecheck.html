Page check

Opens app/babel-phase1.html and app/babel-atlas.html for real, in frames, and asserts they work — that they boot, that the panels fill, that the keys do something, that neither threw on the way, and that neither had a draw call rejected. Nothing in npm test executes either page. Every browser-side defect this project has had was found by a person looking at it: a ReferenceError that blanked the room sentence while 176 assertions passed, a completion poll that stalled forever in a background tab, an atlas drawing every reading room as a gallery. This is the gate for that class. Like core/conformance.html, it is run by opening it.

§21 is the reason for the last of those, and for the backend line at the top. An over-read of a vertex buffer is an error on Metal and a shrug on D3D11, so the atlas was blank on every Mac for four days while looking perfect on the machine that wrote it — and it boots, fills its panel and answers its keys the whole time it is blank. Reading getError() is only half of that gate. On the machine that wrote the bug the queue is empty and this page passes. The other half is running it again under a second backend, which is why every result here says which one it was: --use-angle=metal and --use-angle=swiftshader, each with its own --user-data-dir. (gl is not a third option on Apple silicon — it yields no WebGL2 context at all, and this page fails loudly rather than skipping, which is right.)

The first load on a machine links the prototype's shader, which takes about a minute and a half; a second backend links it cold again. Both frames stay on screen so a failure can be looked at as well as read — and because a frame that is off screen gets no rAF, which is most of what is being checked.
