# Session report — 12 September 2026

What was attempted, what was expected, what happened, and where it fell short.

Nine commits, `cc094eb..beb4a4e`. Written at the end of the session rather than
during it, so the shortfalls are the ones that survived to the end rather than
the ones that felt worst at the time.

---

## 1. The release items (R1–R5)

**Attempted.** An inbox document argued the repository is "a finished thing that
never shipped" and listed five finishing tasks. They were folded into
`ROADMAP.md` as a new `## Release` section ahead of everything under `## Open`,
and then done.

**Expected.** An afternoon. A page gate that reads `getError()`, a committed
conformance result, a README that says what the thing is, a tag, and one framing
decision.

**Happened.** All five closed. Two of them did not work the way they were
planned:

- **R1 — the page gate.** The plan was that reading `gl.getError()` would catch
  the §21 class. It does not, on its own. Putting §21 back and running two
  backends: ANGLE Metal fails 2 of 29 assertions; **ANGLE SwiftShader passes 29
  of 29 on the same broken page**, because it serves the over-read as zeroes and
  the lattice still looks correct. The second backend is not redundancy, it is
  the mechanism.
- **R2 — the conformance artifact.** The plan was to commit
  `docs/conformance-report.html` and link it. GitHub renders a committed `.html`
  as source, so the link alone would have shown a reader markup instead of a
  result. The screenshot is what actually carries above the fold.

**Fell short.**

- **The first version of the page gate was vacuous and passed.** The atlas draws
  under `requestAnimationFrame` and publishes its handle before the first frame,
  so the error queue was read before any `drawArrays`. It was empty on every
  backend. Caught only by deliberately reintroducing the bug.
- **The first committed conformance report named the wrong commit.** It was
  captured with `conformance.html`'s own provenance changes still uncommitted,
  so the stamp pointed at code that was not the code that ran. Recaptured.
- **R5 was not a decision this session could make** and was put to David.

## 2. The four live defects

**Attempted.** The roadmap's closing paragraph named 1b, 1d, 2 and 4 as live.
All four were taken.

| item | expected | happened |
|---|---|---|
| **4** — torn book covers at a grazing angle | "may already be gone", same overshoot family as the spine mottling | **Still there, different cause. Fixed.** |
| **1d** — bad normals rise with range | find the cause, or show the rise is a view artifact | **The rise does not exist.** 9 of 10 views fall |
| **2** — a 160 ms worst frame | find what the spike correlates with | **Did not reproduce in 6,895 frames** |
| **1b** — seam and renderer disagree | the live one that can corrupt a citation | **Already closed by §19; the paragraph was stale** |

**Item 4 in detail.** `shelfDist` sampled one slot per wall, the nearest by
lateral index, and a book does not fill its slot — `BOOK_W*0.90` in a `BOOK_W`
pitch, a depth varying by up to 0.04 m, and 3.5% of slots empty. The distance
over-reports and `t += d * 1.00` steps past the surface. Invisible head-on;
at a grazing angle the ray runs parallel to the spines and 0.04 m sweeps a long
way along the wall. Fixed by evaluating the nearest slot and its two
neighbors. Renderer 1.0.0 → 1.1.0. Bug log §22.

**Fell short.**

- **The fix is not free and the cost was taken unilaterally.** Matched at
  1280×773: **+4.6%** on the view with the long sightline and **+11–14%** on two
  short ones. The step-scale alternative was rejected because its cost lands on
  the long view, which sets the auto-scaler. That is a defensible trade, but it
  is a frame-time regression accepted without a second opinion.
- **1d's metric is not provably the one that filed it.** "Bad normal" here is
  `|n.y|` between 0.12 and 0.88. The filed figures (0.72% / 3.45%) may have used
  a different test, so only the *sign of the trend* is comparable, not the
  absolute numbers.
- **2 is not closed and should not be read as fixed.** A 160 ms gap with no long
  task is a GPU or compositor stall, and nothing here can see one. It needs the
  reporter's machine.

## 3. Item 7 — the last hand-written mirror

**Attempted.** `volumePresent` was a hand-written twin of a hash living inside
the shader, guarded only by a statistical test. The roadmap said to extract it
"the next time `mapAt` is opened for any other reason", and item 4 opened it.

**Expected.** Move the GLSL into `core/babel-glsl.mjs`, add the slots to
`core/vectors.json`, and let the existing GPU conformance harness cover it.

**Happened.** Done. `VOLUME_GLSL` splices in at `@glsl-volume` like the other
three generated regions; 51 shelf slots; four lanes each. **500 GPU integers →
704.** The spine tint turned out to have no twin at all — the shader read bits
16–31 of the same hash for a color the core did not know existed, so nothing
could have checked it even in principle.

**Fell short — and this is the one worth reading.**

**The first version of the check was worthless and I believed it.** It passed
**700 of 700 integers on a shader whose threshold had been deliberately moved**
from `0.035` to `0.0351`. The sample was 48 scattered slots and "the first empty
slot found", none of them near the boundary, so nothing flipped. It was exactly
as vacuous as the statistical test it replaced, for exactly the same reason, and
it took putting the bug back to find out.

Fixed by scanning 420,000 slots and pinning the two closest to the threshold
from either side (0.034988403 / 0.035003662). The drift now costs 1 mismatch
named by slot; `104729 → 104728` costs 118.

**That is twice in one session that a new gate was vacuous on first write.**
Both were found the same way and neither would have been found by running them.

## 4. Item 5 — rung 6 at scale

**Attempted.** A distribution for a real reader, weaker readers for a spread,
and the assisted/unassisted gap. No credential was present. When a credential
path was suggested, reading it was blocked as credential exploration; that block
was respected rather than worked around. David then pointed at a local AI hub.

**Expected.** A model row beside `honest` / `fabricator:3` / `adversary`, and a
spread across reader strengths showing whether the task is hard or the oracle is
merely working.

**Happened.** `core/policy-local.mjs` puts the same reader loop against an
OpenAI-compatible endpoint on this machine — same seam, same brief, same
grammar, same oracle, same start points, only the reader changes. It talks plain
`fetch`, so it needs **no dependency at all**, making it the only rung 6 path
that keeps the repository's dependency-free promise.

The baselines were re-taken under core 0.6.0: honest **1.000**, fabricator:3
**0.625**, adversary **0.000**, over 2,943 checked claims.

| reader | excursions | claims | ended out of context | pages held |
|---|---|---|---|---|
| Qwen3.5-4B | 5 | **0** | 5 of 5, step 4–7 | 3–4 |
| Gemma 4 12B | 3 | **0** | 3 of 3, step 4–6 | 4 |

A page costs **2,500–2,800 tokens** of transcript, so the floor is arithmetic:
roughly `2,000 + 2,650n` tokens for *n* pages. An 8K window buys three pages.

**Fell short, and this is the largest shortfall of the session.**

- **Item 5's actual goal is unmet.** There is no distribution, no spread across
  reader strengths, and no assisted/unassisted gap. Two readers scored
  **undefined**, not good and not bad — neither got far enough to make a single
  checkable claim.
- **Two hours were spent on an assumption one `grep` would have killed.** Gemma
  was run because the machine's guide lists a 256K context. The endpoint serves
  `-c 8192` to both models (`~/.llama-swap/config.yaml`). The model's ceiling and
  the server's are different numbers and only the second one matters. The guide's
  capability table was taken as the effective limit; it is not.
- **The unblock is a change to David's machine, not this repository**, and was
  not made: `-c 32768` in the `[serve]` table of
  `local-ai/machines/mac-mini.toml`, then `local-ai-setup serve`. That would hold
  about eleven pages, which is a 24-step excursion.
- **The frontier row still needs a key and the SDK**, and neither is present.

## 5. Harness faults found while measuring

Recorded because each one produced a confident, wrong number before it was
caught, and two of them were mine.

| fault | what it reported | how it was caught |
|---|---|---|
| `st.div` sets the divisor but does not resize the drawing buffer | the item 4 fix as a **3× speedup**, comparing 1280×773 against 640×387 | the absolute numbers moved between sessions for no reason |
| `gl.finish()` returns before the GPU is done across Chrome's command buffer | a 1M-pixel raymarch at **0.0 ms** | the number was impossible |
| the page gate read the error queue before any draw | a gate that **could not fail** | reintroducing §21 |
| the volume vectors held no slot near the threshold | **700 of 700** on a drifted shader | moving the threshold on purpose |

The first two now assert their own preconditions — the timing harness refuses to
report a buffer-size mismatch.
