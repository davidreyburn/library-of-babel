GPU conformance — a recorded run

The output of core/conformance.html, captured so it can be read without cloning anything. It is a page you open; this is what it said.

What it proves. The Library is a pure function of an address, and that function exists twice: once in JavaScript, which the agent and the tests walk, and once in GLSL, which the renderer draws. The GLSL is a port, not a copy — it has no Math.imul and no 53-bit doubles, so the same arithmetic is written differently and can only be trusted by being run. This harness runs the shader's own copy over 125 cells and 51 shelf slots, reads the results back through an RGBA32UI framebuffer so they are the integers themselves rather than pixels inspected by eye, and compares all 704 of them against what the CPU computes.

Why two backends. Because one is not evidence. A draw call that one driver serves and another rejects is the defect class this project has already been bitten by — see bug log §21 and §21a — and a result from a single GPU cannot see it. Both runs below are the same commit and the same vectors on the same machine, under two different ANGLE backends.

Reproducing it

npm start
open http://127.0.0.1:8731/core/conformance.html

For a second backend, Chrome takes --use-angle=metal and --use-angle=swiftshader, each with its own --user-data-dir so the flag takes. The page prints its own backend, core version and timestamp, which is what makes a capture like this one worth keeping.
